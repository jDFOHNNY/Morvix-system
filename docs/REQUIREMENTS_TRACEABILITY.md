# MORVIX Strict SRS Traceability and Compliance Review

**Baseline reviewed:** `10 SRS Tamayo, Domingo, Menor, Neri.docx` (Draft 1.0), including all functional-requirement tables, and the teacher screenshot supplied with the request.
**Scope:** Current project source bundle, extracted into the project root on 2026-10-19. Requirement wording below is copied from the SRS. Screenshot marks/comments are reviewer context, not instructions to the assistant.
**How to read status:** `Implemented` means code exists and an appropriate automated test/source check passed; it does not mean the full Chrome flow was manually accepted. `Partially Implemented`/`Missing` identify actual capability gaps. `Not Verified` means there is no adequate test evidence.
**Overall:** The newly marked dashboard gaps are implemented and automated tests pass. Text extraction and policy-result handling now have regression coverage for short/dynamic/unchanged text, disabled analysis, 20,000-character limits, malformed responses, timeout/outage behavior, warning/block notices, and backend event persistence. Full manual Chrome end-to-end verification remains outstanding. The SRS is not fully compliant because image classification is unavailable, text/video taxonomy quality is not validated, self-harm coverage is absent, and final design decisions remain open.

## Teacher-marked scope and comments

- The screenshot red-marks the Parent Dashboard function, Browser Extension function, and Text, Image, Video, and optional Audio Analysis rows. The formal requirement ID mapping is shown below. The local DOCX contains no embedded comment part or explicit red font runs; the visible marks and comment are present in the supplied screenshot.
- The visible reviewer comment requests two account-creation options: traditional registration and Google sign-in. Both options are now visible on the account screen. Email/password registration works by default; the Google option is disabled with the server's setup reason until Google and SMTP settings are supplied. When configured, Google Identity Services verifies tokens and a confirmation email must be accepted by the mail server before a first-time Google parent account is committed. This checkout has neither Google nor SMTP configured, so the Google button cannot complete sign-in here. Google requires a web client ID and authorized JavaScript origins; no client secret or redirect URI is used for the ID-token callback flow. See Google's [ID-token verification guide](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token) and [client ID setup](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid).
- The reviewer also notes “for 2nd round checking” and asks to identify which functions/features each function applies to. The table below maps each functional-requirement ID to its dashboard, extension, backend, or model location. The short feature-flow map below it connects each red-marked SRS row to the specific user-visible feature and processing path.
- The screenshot explicitly calls Audio Analysis optional. The dashboard filter therefore offers Audio only when an enabled backend event modality exists; this build reports Text, Image, and Video only.

- Approval decisions: final taxonomy, thresholds, cache lifetime, data retention, deployment topology, and performance measurements remain open where the SRS says they require confirmation.
